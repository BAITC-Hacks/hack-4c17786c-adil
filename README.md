# Beeline Campaign Agent

Рабочая первая версия агентской системы для HackAlem AI / Beeline. Агент исследует аудиторию, адаптивно проводит пилоты и возвращает 1–10 кампаний в пределах бюджета и охвата.

**Реализовано:** автономный Python-агент, пять логических ролей, адаптивные пилоты, подбор кампаний и каналов, контроль лимитов, воспроизводимый `submission.csv` и локальное веб-приложение Campaign Studio. LLM для запуска не нужен. Данные синтетические.

## Интерфейс: запуск в один клик

На Windows откройте `start_app.cmd` двойным щелчком. Скрипт использует Python из `.venv`, доступного окружения Codex или установленный Python 3.12 и открывает приложение в браузере. Зависимости из `requirements.txt` должны быть установлены; на подготовленном компьютере они уже есть.

На любой платформе из подготовленного окружения:

```bash
python app.py --open
```

Интерфейс: **http://127.0.0.1:8765**. Данные подготавливаются автоматически из локального архива. Оставьте окно запуска открытым; Ctrl+C завершает приложение и останавливает незавершённые задачи. Повторный запуск открывает уже работающее приложение. Если порт занят другой программой, используйте `python app.py --port 8766 --open`.

В приложении можно:

- запустить агента с выбранным seed, лимитом пилотов и временем работы;
- выполнить серию из 2–20 прогонов для проверки устойчивости;
- видеть реальные события пилотов и состояние фонового запуска;
- остановить задачу, открыть историю и сравнить несколько запусков;
- изучить аудиторию и тарифы, подготовить данные и запустить тесты кнопкой;
- скачать план CSV, HTML-отчёт, JSON и таблицу сравнения серии.

История хранится в `.local/runs/` на этом компьютере и сохраняется между запусками приложения. Каталог исключён из Git. Задачи выполняются последовательно в отдельном процессе; интерфейс остаётся доступным. Незавершённые после аварийного закрытия задачи помечаются прерванными.

**План эксперимента и файл для сдачи различаются.** `campaign_plan.csv` содержит план выбранного эксперимента. `submission.csv` доступен только для seed 42 с настройками агента по умолчанию (20 пилотов, 240 секунд). В серии файл для сдачи берётся именно из этого прогона, даже если лучший локальный результат показал другой seed. Кнопки экспорта и пояснения в интерфейсе указывают назначение файлов. Корневой `submission.csv` эксперименты не перезаписывают.

Это локальное приложение: сервер слушает только loopback-адрес, не отправляет реальные сообщения абонентам и не размещается в интернете. Дополнительные веб-библиотеки, Node.js и сборка frontend не нужны.

## Запуск

Нужен Python 3.12. Из корня репозитория:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python setup_case.py
python local_eval.py
python make_submission.py
```

`setup_case.py` восстанавливает CSV из сохранённого в репозитории архива, проверяет SHA-256 и не перезаписывает изменённые данные. Google Drive, API-ключи и интернет после установки зависимостей не нужны.

## Как работает система

Точка входа — `agent.py`: `Agent().act(env)` возвращает кампании с фильтрами, `target_tariff` и `channel`.

1. **Оркестратор** управляет общим состоянием, временем и ресурсами.
2. **Аналитик** формирует сегменты и гипотезы. История другой выборки используется только как слабое начальное предположение.
3. **Экспериментатор** вызывает `env.run_pilot()`, обновляет оценки, чередует разведку и повторные проверки, адаптирует выборку и проверяет альтернативные каналы.
4. **Оптимизатор** выбирает портфель с запасом на шум, учитывая стоимость, охват и приблизительное пересечение с пилотами.
5. **Контролёр** проверяет тарифы, фильтры, каналы и последовательное расходование ресурсов. Экспортирует только семь допустимых колонок.

При ошибках пилотов агент использует фактические остатки ресурсов и запасную логику. Если прибыльный план не подтверждён, выбирает минимальную доступную кампанию через самый дешёвый канал с предупреждением. При наличии бесплатного push резервный вариант бесплатен, но прибыль не гарантируется. Если нет аудитории или контактов, допустимая кампания невозможна: возвращается пустой список с диагностикой.

python -m unittest discover -s tests -v

После `demo.py` откройте [artifacts/dashboard.html](artifacts/dashboard.html) локально в браузере. Это автономный HTML, без сервера и внешних ресурсов. На GitHub он отображается как исходный файл. Отчёт содержит аудиторию, пилоты, расходы, кампании и объяснения; полные данные — в [artifacts/demo_report.json](artifacts/demo_report.json). Прогноз дополнительного эффекта финального плана отличается от результата оценщика, включающего фактические mock-эффекты и все пилоты.

## Структура и исходные материалы

- `agent.py` — точка входа и оркестратор.
- `app.py`, `start_app.cmd` — запуск локального приложения.
- `web/` — frontend: HTML, CSS и JavaScript.
- `webapp/` — HTTP API, очередь задач, хранение истории и фоновый исполнитель.
- `campaign_agents/` — анализ, пилоты, оптимизация, контроль, состояние.
- `tests/test_agent.py` — поведение, ошибки, лимиты и крайние случаи.
- `demo.py`, `artifacts/` — отчёт и сохранённый пример.
- `setup_case.py`, `vendor/` — полный неизменённый пакет участника и восстановление CSV.
- `scripts/validate.py`, `submission.csv` — воспроизводимая проверка и сдаваемый план.
- [docs/architecture.md](docs/architecture.md) — устройство и ограничения.

`local_eval.py`, `make_submission.py`, `environment.py`, `mock_environment.py`, `scoring_core.py`, `agent_template.py` и `PARTICIPANT_GUIDE.md` сохранены из пакета без изменений. Все исходные CSV и PDF находятся в `vendor/beeline_case_participants.zip`.

Для сдачи сохраняйте `agent.py` вместе с `campaign_agents/`, `requirements.txt`, `submission.csv` и общедоступными данными кейса. Агент не импортирует оценщик и скрытую модель. Штатные инструменты проверки используют среду по исходному контракту.

## Практические ограничения

Оценка неопределённости использует опубликованный шум и нормальное приближение. Эффект узкой подгруппы переносится с пилота родительского сегмента. ID участников пилотов недоступны, поэтому их пересечения оцениваются приближённо. Выбор портфеля эвристический, без гарантии глобального оптимума. Эти допущения перечислены в отчёте.

LLM остаётся необязательным следующим этапом. Время в интерфейсе — внутренний бюджет решений агента; загрузка процесса, данных и оценка результата добавляют небольшие накладные расходы. Шаблон требует 5 минут без интернета, актуальное ТЗ — 10 минут с разрешённым LLM; автономное ядро соответствует более строгому варианту. Серия состоит из отдельных независимых прогонов.
